Serial Monitor access on managed (work) computers

The MegaNet Serial Monitor uses the browser's Web Serial API. On a personal computer, clicking Choose COM port… opens the browser's port picker and you select the device. On a managed work computer, Chrome and Edge enterprise policies can block Web Serial entirely — the browser then rejects the request instantly and silently, without ever showing a picker, and the app can only report that the picker was suppressed.

Symptom guide

What you seeWhat it means
"The browser refused to show the port picker" (no dialog ever appeared) Web Serial is blocked — usually by enterprise policy on a managed machine. See the IT request below. Nothing you change in the app can fix this.
The picker opens but the list is empty The browser can't see a serial device: cable/driver problem, the device is on a VDI/remote session without USB redirection, or another program holds the port. This is a device/OS issue, not a permissions one.
"Web Serial isn't available in this browser" Non-Chromium browser (Firefox/Safari) or the page was opened from a file:// path. Use Chrome or Edge over https or localhost.
"Failed to open serial port" after picking The OS refused the open — almost always another program (PuTTY, a logger, another browser tab) already has the COM port open.

What to ask IT for

Web Serial permission in Chrome and Edge is controlled by group policy. Either of the two options below works; option B never shows a picker at all, which some security teams prefer because it grants exactly one site access to exactly the approved devices.

Option A — allow this site to ask. Add the app's origin to SerialAskForUrls so the normal port picker appears for this site only:

Policy:  SerialAskForUrls
Value:   ["https://cdomotor-g.github.io"]

Chrome registry: HKLM\Software\Policies\Google\Chrome\SerialAskForUrls\1 = "https://cdomotor-g.github.io"
Edge registry:   HKLM\Software\Policies\Microsoft\Edge\SerialAskForUrls\1 = "https://cdomotor-g.github.io"

This overrides a global block from DefaultSerialGuardSetting = 2 for this one origin. If the site also appears in SerialBlockedForUrls, it must be removed from that list.

Option B — pre-approve the device, no picker needed. Grant the site access to specific USB serial adapters by vendor/product ID:

Policy:  SerialAllowUsbDevicesForUrls
Value:   [{"devices": [{"vendor_id": 1027}], "urls": ["https://cdomotor-g.github.io"]}]

(1027 = 0x0403, FTDI, as an example — use the VID of the actual adapter, visible in Windows Device Manager under the port's hardware IDs.) Pre-approved ports appear in the Serial Monitor under "Previously allowed" and connect with one click; the blocked picker is never involved. For non-USB (motherboard/PCIe) COM ports, SerialAllowAllPortsForUrls with the same origin is the equivalent.

Check what's currently applied: open chrome://policy (or edge://policy) and search for serial. DefaultSerialGuardSetting of 2 means "block serial on all sites unless a policy above allows it"; 3 means "ask" (the default behaviour). These pages are read-only — only IT can change the values, but a screenshot of them is exactly what IT needs to see with the request.

Notes for the security team

  • Web Serial only ever grants access per-site, per-device, with an explicit user gesture (or an explicit device allowlist via policy). It cannot enumerate or open ports silently.
  • MegaNet is a static single-page app served from GitHub Pages (cdomotor-g.github.io/MegaNet); serial data is processed entirely in the browser and never leaves the machine.
  • Policy reference: Chrome serial policies · Edge serial policies.
