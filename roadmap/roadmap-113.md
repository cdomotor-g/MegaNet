Plus **three registries that used to silently under-report** if a new feature forgot them. **All three are now fixed, and fixed the same way** — the module declares its own participation in its own file. M3 did the first, #142 did the other two at `7e86e51`:

- `MemMeter`'s registry — **all three lists are now in `mem-meter.js`**: the `HOLDERS` array (**44–57**), the byte-measurement map in `memoryReport()` (**175–183**), and the `release()` switch (**342–346**). Verified in the UI after M3's move and again after #144 — every holder renders and `release()` runs for each releasable key.

**Protocol:** one designated agent serialises edits to these, or they are edited in a pre-agreed order. Never concurrently. **This applies across the six U-issues in EPIC #107 in particular** — partitioning by tab does not remove these.

### 5. The load order in `index.html` is a contract (new — M1 / #132)

```
leaflet → maps-data.js → core.js → app.js → rf-changes.js → workbench.js → …the 14 M3 modules… → …the 10 M2 modules… → init.js
```

**Thirty-four local scripts at #118**, up from thirty-three at #149 and #146+#148, and the epic that was growing this list is closed. `inspections.js` was inserted after `station-editor.js` at #116, `maintenance.js` immediately after it at #117, and `attachments.js` between `station-editor.js` and `inspections.js` at #149 — insertions, not reorders, and every position is free for the usual reason: `npm run toplevel` says none of them executes anything at load. `attachments.js` sits *above* its two callers only because that reads right; nothing requires it. `history.js` was inserted after `maintenance.js` at #118 on the same reasoning — it reads both of the files above it, and nothing requires it to be below them either. `app.js` still sits where it does because it is the remainder — the app shell, the Stations map core and RF Environment.

M3's and M4's files are inserted *between* `app.js` and the modules below rather than appended after them, and that is not cosmetic: `concat-verify` compares bytes in `index.html` load order, so code lifted off the end of `app.js` only lands in the right place in that order if the files holding it come immediately after `app.js`. Inserting is still adding to the order, not reordering it — no existing file moved relative to another.

Classic scripts sharing one global scope, deliberately — see #129 for the four independent reasons ES modules were rejected. Two rules follow, and they bind every issue that touches the front end, not just #129's children:

- **Add files to that list; do not reorder it, and do not move a file within it.** `index.html` says so at the top of the script block.
- **`init.js` is the only file that executes at load.** Everything else declares. That property is what makes a module movable to its own file without its position mattering, and it is what retired the two TDZ crashes in #131. One top-level statement that runs on sight takes it back. If you need something to happen at startup, it goes in `init.js`.

**Two** files execute anything at load, and both were found by running the check rather than assuming it. `network-maps.js` reads `window.MegaNetMaps` at load, so `maps-data.js` must precede it — true by construction, not by coincidence. And `datastore.js`'s `_dbToken` reads `sessionStorage` for a saved access token; it touches nothing outside its own file, so it constrains nothing, but it is the shape to look for.

**This is `npm run toplevel` now, and it runs in CI (#142 / `730aeab`).** It parses every script `index.html` loads and fails on a statement that executes at load, descending into module IIFEs — which is where every module lives and where a stray registration would hide. Exactly **three** statements in the app run at load; each is listed in `ACCEPTED` at the top of `test/toplevel.mjs` with the reason it has to, so the list is a decision rather than a habit. Adding to it makes that file's position mean something.

The measurements that motivated it, kept because they are the argument for running it rather than reasoning: parse the file and report every top-level statement whose evaluation is not an inert initialiser. Across all of `app.js` before M3 that was **448 statements — every one a declaration, four `window.X` exports, and that one `try`/`catch`.** M4 ran it again on its two new files: 41 statements in `rf-changes.js` and 72 in `workbench.js`, all function and const declarations plus the return, so both positions are free *including relative to each other* even though `workbench.js` holds a reference to `RfChanges`. **Three milestones running raised an ordering constraint that measurement dissolved in minutes** — `Alert2` ↔ `Serial` in M2, `PathProfile` ↔ `LinkBudget` in M3, `RfChanges` ↔ `Workbench` in M4. Run the check; do not reason about it.

`?v=` is one shared stamp across every script, bumped together (currently `20260814g`). **`styles.css` was carrying its own stale stamp (`20260813a`) and is now on the shared one** — it is a slice of the same program and deploys with it, so a separate stamp could only ever produce a mismatched pair. `core.js` must always carry one — `APP_VERSION` reads the build back off its own script tag, and an unstamped `core.js` makes every bug report say `'dev'`.

### 6. The design system exists now, U1–U6 apply it rather than decide it, and a check now holds them to it (#109 / `10ee6b9`; extended by #137 / `ffce935`)

| Where | What |
|---|---|
| `styles.css`, the block at the top | The tokens, and the contract in short form |
| `core.js`, `BREAKPOINTS` | The breakpoint scale — the only place the widths exist |
| `core.js`, `announce()` | The live-region policy, stated above the function |

**The one rule:** if a U-issue needs something that is not there, it is added *there* and written down — not decided locally. A number typed into one tab's CSS is a decision the next tab cannot find. Four consequences worth naming before allocating #136–#141:

- **Six named breakpoints, and no seventh.** `xl` 1400 · `lg` 1100 · `md` 900 (the nav rail — `NAV_AUTO_COLLAPSE_PX`) · `sm` 700 · `xs` 560 (the drawers — `isPhoneNav()`) · `xxs` 380. - **One table pattern, one chart pattern.** Both written down, because six issues deriving different halves of either is the most likely way this epic produces six products in one window. The chart answer is the one #138 and #141 were told to agree with each other: name carries the number, one-sentence summary, real data table one activation away.
- **The focus ring is not a per-tab decision.** One `:where()` rule at zero specificity — override it with one selector if you must, but `outline: none` outside the two-entry allowlist goes red.
- **A colour change is a system change.** A new token needs a dark-theme value and a line in the contrast contract in `test/shell.mjs`, or the check fails. ~~And a palette change still does not reach ArroData's SVG, which writes literals for the PNG export — #141's, by hand.~~ **Closed by #141 at `a22f72e`**: that chart still writes literals (a `var()` resolves to nothing once the picture is handed to a canvas) but resolves them off `--ad-series-1…12` at draw time, so a palette change reaches it on the next `repaint()`. **What #109 deliberately left:** five tabs render an `<aside>` inside `<main>` — Stations' filter pane, both Workbench rails, Export's sidebar, Radio Path Maps' left column, ARRO Data's side — each an unnamed `complementary` landmark. That is #136/#139/#141/#137's, and the rule is in the design system: a landmark inside a tab carries an `aria-label` or it is not a landmark. **Radio Path Maps' is done at #137; Export's sidebar and ARRO Data's rail at #141; both Workbench rails at #139** ("Investigation setup" and "Suspects and actions"); **and Stations' filter pane at #136** ("Filters and map display"). **The ledger is closed — every `<aside>` in a tab is named.**

**What #137 added to the system, and what the remaining five inherit** *(`ffce935`)*. Three things, and none of them is about its own three tabs:

- **`npm run tabs`** — the Definition of Done, checked, per converted tab. See constraint 1. **Add your tab ids to `CONVERTED` in `test/tabs.mjs` in your landing commit**; a tab left off that list is a tab nobody is holding.
- **Two more table patterns, 7 and 8.** A `.tall`/`.medium` `.table-wrap` scrolls, and `overflow: auto` on a div is keyboard-scrollable in Firefox and nowhere else — so it is `role="region" tabindex="0" aria-labelledby="<the panel heading's id>"`. And `<tr onclick>` is a mouse affordance and nothing else, so a clickable row carries a real `<button class="row-open">` in its name cell, styled as the text it replaces, stopping the event so the two never both fire.
- **A pattern-2 bug that affected every table in the app.** Pattern 2 says the fixed layout is dropped below `md` so each column takes what it needs — and it was not happening on any table with a `<colgroup>`, because percentage `<col>` widths are still honoured under `table-layout: auto`. Pass Ranges' six columns came out at 16% and 8% of a 340 px wrapper. `.table-wrap col { width: auto !important }` in the responsive block fixes it everywhere; **if you have been laying a table out against a colgroup, its phone rendering has just changed.**

**And one decision worth knowing before #136 and #140.** Pattern 8 — *a graphic that is a shortcut for controls beside it* — is the exception to "never `role="img"` on something interactive", and it has three conditions: every operation the graphic offers is on a named control in the same panel, nothing inside it is in the tab order, and its name says where the operable version is. Radio Path Maps' basin drawing is the first instance (a hundred clickable polygons, eight region chips beneath them). **The Stations map and the Ghosting Graph are not that shape** — both offer operations that exist nowhere else — so #136 and #140 get the chart pattern, not this one. **#140 has since found the sharp edge of that rule at revision 53**: the graph was *already* carrying `role="img"`, over an SVG whose every node was a named tab stop, and the role was silently discarding all of those names. It is `role="group"` now, with the chart pattern's part 3 — the addresses in view, as a table — beneath it.

**What #138 added to the system, and what the remaining three inherit** *(`532b290`)*. Six things, and — as with #137 and #141 — almost none of it is about its own two tabs:

- **Pattern 10 — a sortable column header is a button, and the `<th>` carries `aria-sort`.** Nineteen headers across the two RF tables were `<th style="cursor:pointer" onclick="…sort('score')">`: not in the tab order, no role, and a screen reader was never told the table was sorted at all. **It includes the focus restore, which is the part that is easy to miss** — a sort replaces the header row's `innerHTML`, so the button that was just pressed no longer exists and a keyboard sort drops the user on `<body>`. Exactly what `renderTabs()` used to do to the nav, and the same fix.
- **Pattern 11 — a graphic wider than its column scrolls in a named region.** Pattern 7a for something that is not a table, keeping #141's split: the scroller is the *control* and takes the tab stop, the `<svg>` is the *picture* and takes the numbers. ~~**#140 has three of these waiting for it**~~ — **#140 closed at revision 53; its wide graphic is the Ghosting Graph's stage, which owns its own pan/zoom and answers to the chart pattern rather than to this one.** ~~#136 has the elevation profile and the link budget.~~ — **#136 closed at revision 54: both are inside the link-budget panel's own column and neither is wider than it, so neither needed the scroller; what they did need was captions, which the drawn-path seed found the moment it existed.**
- **Four primitives the app had been writing out by hand**: `.link-btn` (a `<button>` that reads as a link — the counterpart to `.btn-link`, for the dozens of `<a href="#" onclick="…;return false">` in this app, which are announced as links and navigate to the top of the document if the handler throws), `.button-group`, `.control-row` and `.field-num`. **`.button-row` spreads its children apart** — #138 used it for a group of two and got a confirm/cancel pair at opposite ends of a panel; `.button-group` is the one that packs.
- **The ACMA boundary, settled by doing rather than negotiating.** The mechanism palette is the system's (`--acma-mech-*`, seven tokens with a dark set, plus `acmaMechVar()` / `acmaMechColor()` / `cssVar()` in `core.js`). `ACMA_MECH[k].color` **stays the light literal on purpose**: five consumers are Leaflet options, which become SVG presentation attributes, and those do not take `var()`. Those five are the map's and they work unchanged. **The transmitter card is done** — it renders on three tabs owned by three issues, so it is none of theirs to style; #136 and #139 inherit it converted, with a name, `role="dialog"`, focus in on open and back to the opener on Escape. Before this you could open a card on either long tab and, from a keyboard, not be able to shut it.
- **`.table-wrap` is `position: relative`, and this was a real bug in every table in the app.** `overflow` clips a descendant only when the scroll container is that descendant's *containing block*, and an absolutely positioned box's containing block is the nearest **positioned** ancestor — which `.table-wrap` was not. So a `.sr-only` inside a cell escaped the wrapper's clip and put its static x (490 px into an 880 px table) into the document's `scrollWidth`: **the page scrolled sideways on a phone because a screen-reader-only span was doing it.** If you are about to put an `.sr-only` in a cell — and pattern 10's arrow and any glyph column will make you — it is safe now and was not before.
- **Three changes to `npm run tabs`.** A `seed` is **awaited** (both RF tabs parse ~2 MB of ACMA JSON, which is far longer than two animation frames, so an unawaited seed checks the loading state); a `seed` **runs in the overflow pass too** (that loop was measuring whatever the tab shows on arrival, and it is where the widest thing on RF Changes lives); and **a tab with two mutually exclusive views gets two `CONVERTED` entries**, because the default is the half with less markup in it. All three apply to #136 and #139 directly.

**And a fourth palette, which makes it a pattern rather than a coincidence.** The region fills (#137), the ARRO series (#141), the ACMA mechanisms and the RF Changes series (#138) were all colours typed into a JavaScript file that the dark theme could not reach, and all four were found the same way — by converting a tab, not by looking at one. **If your tab draws a colour it typed itself, it belongs in the token block**, with a dark value, and categorical sets stay out of the contrast contract. One thing colour must never be: the timeline's lane labels were *text* in the mechanism colour, and are `--text` with a coloured key square in front now.

**Three surfaces #138 deliberately left** — ~~`workbench.js`'s `#7b1fa2` legend literal and two `ACMA_MECH[…].color` reads~~ (**done at revision 52 by #139**, threat-square divIcon included); the map's ACMA popup still writes a mechanism pill with an inline `background` (**#136**, the one left).

**Touch targets have two floors and now say so.** The app-wide floor is 2 rem / 32 px, past WCAG 2.5.8 (AA, 24 px). EPIC #107's Definition of Done asks 44 px, which is 2.5.5 (AAA). Where they differ, a U-issue's **own** controls take 44; #137's chips and icon buttons are at 2.75 rem under `(pointer: coarse)`. Raising every button in nineteen tabs is nobody's issue on this board.

### Revision 59 — 2026-08-19: the MQTT publisher identity is the bureau station number, not the slug — and the provisioning run is written down

- **The `<station>` topic segment is the bureau (BoM/CBM) station number now** (`0020_mqtt_bureau_number.sql`, applied live, schema 19 → 20). It was the `stations.json` slug since `0008`, and the reasoning `0008` gave for that — *a second identifier for one site is a mapping table somebody has to keep in step* — was right about the principle and wrong about which identifier. **The slug is derived from the station's name** by `core.js`'s `slug()`, so `loudoun_br_al` exists because somebody typed "Loudoun Br AL" into this app: nobody outside MegaNet knows it, renaming a station moves it, and the copy it moves in is logger firmware, which costs a site visit to change. The bureau number is on the site card, in the Bureau's systems and on the paperwork, and it is not ours to move — which is the entire property a key needs.
- **Sites with no bureau number publish under their station id**, resolved by `meganet.resolve_publisher()`. That is 18 of 3,174 rows and not one of them a gauging station — they are repeaters, radars, base stations and a test rig, which honestly have no bureau number and never will. **This is one rule, not two identifiers**: a site has a number or it has not, and the database answers either without a mapping table.
- **The rule is safe to state that plainly because it was measured before it was written.** 3,156 of 3,174 stations carry a number and every one is distinct; no station id is purely numeric; no station id equals a *different* station's number; every id and every number already satisfies the topic-segment grammar. **The two namespaces are disjoint**, so "number first, then id" can never be a coin toss — and that is a fact about today's data, so `station_number_unique_idx` now holds it there.
- **The unique index is the load-bearing half, and it is there for a failure mode that had no symptom.** `resolve_station()` answers NULL rather than guessing when a number matches two stations — a safe silence when the number was one address form among several, and *not* safe when it is the publisher identity: a duplicate would make **both** stations unroutable, silently, and the first anyone would know is a gauge that stopped reporting. The index moves that failure to the moment somebody saves the second station. Live data satisfies it with zero duplicates, so it could not fail on apply.
- **`station_status_converge()` gained a fourth case, and skipping it would have re-opened #162 through the front door.** `0019` re-resolves an `a:` form, an `s:` form and a row whose `station_id` is already set; a bare segment that resolved to nobody was left alone, which was correct while the segment was a slug — *a slug that names nobody will never name anybody*. - **Applying it to the live project moved no data.** All 150 non-canonical `station_status` rows are `a:` address forms resolving to no station, exactly as revision 50 recorded; the new bare-segment case matches none of them, and a dry run confirmed that before the migration went on.

### Revision 39 — 2026-08-16: the base-station program was reading its serial port wrong, and now shows every step of it

- **`logger/base-station-http.CR300` rewritten at HEAD** — a session request against the program that landed at `334f798`, reported as not working on the bench. No issue number, recorded here because #157 is the commissioning checklist for exactly this file.
- **The bug was one parameter.** The program drained the port with `SerialInRecord()` in a loop, passing `1` as the last argument. That argument is `RecordsBackFromNewest` — how many records *back from the most recent* to hand over — so it asked for the record before the newest and returned nothing at all when only one had arrived. It is also the wrong instruction for draining: one call yields one record, so the loop never emptied a port that filled between scans. **A wrong option code that compiles is precisely the failure mode revision 31 named and then walked into anyway**, one instruction further along than the two it had guarded against.

- **One live hole found while scoping, and it loses data silently.** `bridge/src/messages.js` classifies any non-JSON payload as *poison* — acked, counted, never redelivered, because a message that can never succeed must not be retried forever. - **The trap that set #153's model and effort.** HFEM's `T2` carries a **UTC** stamp with an offset appended so a reader can compute *local* time; `T3` carries a **local** stamp with an offset appended so a reader can compute *UTC*. The spec's own examples g) and h) are the same observation written both ways — `T2=20100727030000+10` and `T3=20100727130000-10` are one instant — and an ISO-8601 parser gets the first wrong by 10 hours and the second by 20. **A format with no checksum, whose worst failure mode is a plausible reading at the wrong time.** That is what makes it Opus work, and what makes the spec's ten worked examples non-negotiable as tests rather than nice to have.
